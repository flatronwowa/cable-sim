## Spaces

Явно преобразовывать финальные точки центральной линии в local space только на границе
рендеринга. Внутри солвера спейсы не смешиваются.

## Документация в коде

Для сложной математики добавлять короткие содержательные комментарии:

- что означает constraint;
- где применяется XPBD compliance;
- зачем используется lambda;
- почему нужен конкретный collision pass;
- что делает bending formulation.

Очевидные строки не комментировать. Если используется неочевидная формула, оставить название
метода или алгоритма, по которому её можно идентифицировать.

## Приоритеты разработки

При конфликте требований использовать такой порядок приоритетов:

1. отсутствие прохождения кабеля через collision geometry;
2. сохранение физической длины;
3. численная устойчивость;
4. корректный bending;
5. устойчивые resting contacts;
6. реалистичное friction;
7. визуальное качество mesh;
8. производительность;
9. дополнительные возможности.

При этом пункт 1 не решается способом, полностью разрушающим пункты 2–5.

## Финальное требование

Нужна инженерная реализация физического кабеля, а не демонстрационный rope effect.

Главная модель задачи:

```
anchors + cable physical properties + collision world
  -> initial collision-free topology
  -> XPBD physical relaxation
  -> stable centerline positions
  -> procedural cable mesh
```

Кабель должен вести себя как объект конечной длины и толщины, который физически находится в
3D-мире и контактирует с его поверхностями.

Автоматические тесты и отдельные тестовые сцены в рамках этой задачи не добавляются.
